# Vercel, Neon и Mapbox

Production-деплой на Vercel автоматически выполняет миграции перед сборкой, если задан DATABASE_URL. Проверку подключения и функциональности выполняйте после деплоя.

## Переменные

| Переменная                 | Где доступна                     | Назначение                                                                 |
| -------------------------- | -------------------------------- | -------------------------------------------------------------------------- |
| `NEXT_PUBLIC_MAPBOX_TOKEN` | Браузер, встраивается при сборке | Новый публичный токен Mapbox с разрешёнными URL приложения                 |
| `DATABASE_URL`             | Только сервер                    | Строка подключения Neon PostgreSQL; обязательна для постоянной истории     |
| `SESSION_SECRET`           | Только сервер                    | Случайная строка не менее 32 символов для подписи cookie; обязательна с БД |

Секреты не коммитить. `.env.local` исключён из Git. Не используйте префикс `NEXT_PUBLIC_` для подключения БД или секрета сессии. Mapbox требует именно публичный токен `pk.*`, а не секретный `sk.*`.

Секрет можно сгенерировать в devenv:

```sh
devenv shell -- node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))'
```

## Neon

1. Создать проект Neon и базу PostgreSQL в регионе рядом с Vercel Functions. Для preview предпочтительна отдельная ветка Neon.
2. Скопировать connection string из Neon в `DATABASE_URL` файла `.env.local`. Драйвер `@neondatabase/serverless` выполняет запросы через HTTP; отдельный пул Node.js не нужен.
3. Задать `SESSION_SECRET`.
4. Для ручного запуска выполнить `node --env-file-if-exists=.env.local scripts/migrate.mjs` из корня репозитория (Node.js 24 и установленные зависимости). На Vercel вручную запускать не требуется. Скрипт читает `.env.local`, выполняет SQL-файлы из `migrations/` по порядку в одной транзакции: создаёт `ea_reports`, индекс и очищает старые отчёты сверх лимита 250. Повторный запуск безопасен. Существующие старые таблицы не удаляются.

Не загружайте старый `DB.sql` в Neon целиком: в нём расширение `adminpack`, старые последовательности и тестовые записи. Справочники уже включены в приложение и не требуют отдельного импорта.

## Vercel

1. Опубликовать **новый** репозиторий `emergency-analyzer` в выбранном Git-хостинге и импортировать его в Vercel.
2. Framework preset: Next.js. Root Directory: корень нового репозитория. Если импортируете родительскую папку с обоими архивами, root должен быть `emergency-analyzer`.
3. Node.js: 24.x. Install/build указаны в `vercel.json`: `node scripts/pnpm.mjs install --frozen-lockfile`, `node scripts/vercel-build.mjs`. Скрипт сначала выполняет миграции, затем запускает сборку через `scripts/pnpm.mjs`. Скрипт через npx запускает точную версию из `packageManager`; Corepack не нужен. В devenv команды `ea-*` используют исключительно pnpm из Nix, без этого скрипта.
4. Добавить три переменные для нужного окружения Production/Preview. `NEXT_PUBLIC_MAPBOX_TOKEN` должен существовать **во время сборки**; после смены токена нужен redeploy.
5. Нажать Deploy. Для production миграции выполняются автоматически; ошибка миграции останавливает сборку.

Миграции запускаются перед каждой production-сборкой и должны оставаться идемпотентными. Транзакционная advisory-блокировка сериализует одновременные запуски. Preview автоматически не меняет БД: для отдельной preview-ветки Neon запустите миграции вручную. Без DATABASE_URL сборка проходит без миграций, с хранением отчётов в текущей вкладке. На Vercel не нужны devenv или Nix — используются только Node.js-скрипты. Отдельные API_ADDRESS/PROXY_URL и CORS-прокси больше не нужны — UI и API используют один origin.

## Проверка после подключения

- `GET /api/health` возвращает `status: ok`. Это проверка приложения, не проверка доступности БД.
- Создать сценарий: `POST /api/simulations` возвращает 201 и `persistent: true`.
- Открыть отчёты, перезагрузить страницу и снова открыть расчёт. Удалить тестовый отчёт.
- В другом профиле браузера список должен быть пустым, а чужой ID — возвращать 404.
- Убедиться, что Mapbox загрузился, зоны появляются и движутся, навигация и обязательная атрибуция карты видимы.
- При отключённом токене остаётся обзорная карта и явно показано отсутствие детализации.

Отчёты привязаны к подписанной HttpOnly cookie со сроком один год. Это изоляция анонимных браузерных сессий, не система пользовательских аккаунтов. Очистка cookie или смена `SESSION_SECRET` теряет доступ к прежним отчётам. В БД хранятся максимум 250 отчётов суммарно для всех сессий. Каждая новая запись и удаление старейших выполняются в одной транзакции с блокировкой конкурирующих записей. Порядок: `created_at DESC, id DESC`. При миграции уже накопленная история также сокращается до 250. Пользователь видит только оставшиеся отчёты своей сессии; старые ссылки после удаления возвращают 404. Лимит хранения не ограничивает частоту запросов.

Без `DATABASE_URL` приложение остаётся рабочим, но отчёты доступны только в текущей вкладке, максимум 250 на вкладку. Если БД настроена, но недоступна, API отвечает 503, а не выдаёт временное сохранение за постоянное.

Официальные инструкции: [Next.js на Vercel](https://vercel.com/docs/frameworks/full-stack/nextjs), [драйвер Neon](https://neon.com/docs/serverless/serverless-driver), [Mapbox GL JS](https://docs.mapbox.com/mapbox-gl-js/guides/get-started/).
